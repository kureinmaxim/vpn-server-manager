# SSH-ключ для карточки сервера

Используйте ключ, чтобы не хранить пароль входа по SSH. Сначала проверьте вход по ключу, затем отключайте парольную аутентификацию на сервере.

## Создать и установить ключ

На компьютере с приложением:

```bash
ssh-keygen -t ed25519
```

Задайте фразу-пароль, если нужна дополнительная защита файла. Передайте на сервер только публичный файл `.pub`:

```bash
ssh-copy-id -p PORT USER@SERVER
```

Если `ssh-copy-id` отсутствует, добавьте содержимое публичного файла в `~/.ssh/authorized_keys` через консоль провайдера или документированный способ вашей ОС. Приватный файл на сервер не копируйте.

## Сохранить ключ в приложении

1. В карточке откройте **SSH-доступ**.
2. В поле ключа укажите путь на компьютере, где запущено приложение (например, `~/.ssh/id_ed25519`), или вставьте текст приватного ключа.
3. Для зашифрованного файла укажите фразу-пароль.
4. Сохраните карточку и проверьте, что fingerprint отображается без содержимого ключа.
5. Проверьте вход командой `ssh -o PasswordAuthentication=no -p PORT USER@SERVER`, затем повторите проверку в приложении.

VPN Server Manager читает ключ по сохранённому пути при SSH-подключении; резервный архив содержит путь, но не копирует файл. Вставленный текст ключа входит в зашифрованную карточку и экспорт.

Импорт `~/.ssh/config` поддерживает буквальный `Host`, `HostName`, `User`, `Port` и первый `IdentityFile`. Он не применяет `Include`, `Match`, шаблоны, ProxyJump/ProxyCommand или HostKeyAlias. SSH-agent и аппаратные ключи не настраиваются импортом; SSH-операции приложения используют пароль и ключ, явно выбранные в карточке, и не перебирают локальные identities автоматически. [Подробности и ограничения](SSH_OPERATIONS_MATRIX_ru.md).

## Доверять ключу сервера отдельно

Ключ пользователя и host key сервера — разные ключи. Перед первым подключением независимо сравните host key сервера с fingerprint из доверенного источника, затем сохраните его через OpenSSH в `known_hosts`. Не отключайте эту проверку при смене адреса, порта или сервера.

Отключайте `PasswordAuthentication` только после успешного входа по ключу из новой SSH-сессии и после проверки в VPN Server Manager. Сохраните текущую административную сессию, пока не подтвердите второй вход.
