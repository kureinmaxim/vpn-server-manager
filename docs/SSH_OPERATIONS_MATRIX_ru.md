# SSH: поддерживаемая конфигурация, платформы и права

VPN Server Manager — локальный инструмент одного оператора. Он хранит личный инвентарь в зашифрованном файле и выполняет выбранные проверки по SSH. В приложении нет общих командных ролей, согласований, централизованного журнала действий или безопасной многопользовательской модели. Не используйте общий сетевой файл `.enc` как командное хранилище.

## Импорт `~/.ssh/config`

На странице добавления или редактирования сервера кнопка **«Импортировать из ~/.ssh/config»** явно читает OpenSSH-файл пользователя, под которым запущено приложение. До нажатия файл не читается и не индексируется. Импортируемые значения попадают в обычные редактируемые поля карточки; ничего не сохраняется, пока оператор не сохранит карточку.

Поддерживаются буквальные псевдонимы `Host`, `HostName`, `User`, `Port` и первый `IdentityFile`. Путь `IdentityFile` хранится как локальный путь и не копируется в архив; зашифрованный ключ требует фразу-пароль в карточке. Импорт не читает приватный ключ целиком, не принимает пароль из конфигурации и не ослабляет проверку ключа сервера через `known_hosts`.

`Host *` и другие шаблоны, `Include` и `Match` не разрешаются. `ProxyJump`, `ProxyCommand`, `HostKeyAlias`, `IdentityAgent`, перенаправления и остальные директивы не преобразуются в настройки приложения. Найденные директивы перечисляются по имени без их значений. Если конфигурация зависит от таких правил, приложение может подключаться не тем маршрутом или с другой SSH-идентичностью; проверьте итоговые поля и настройте прямой адрес либо используйте отдельное проверенное подключение.

Импорт не является полной реализацией OpenSSH: режимы SSH-agent, hardware/FIDO keys и ProxyJump пока не имеют отдельного согласованного пользовательского режима и сквозных проверок. Для предсказуемой работы укажите в карточке пароль или поддерживаемый ключ. Не считайте наличие директивы в `~/.ssh/config` доказательством поддержки.

## Матрица платформ и возможностей

| Компьютер приложения | Удалённый узел | Поддержка и ограничения |
|---|---|---|
| macOS | Linux с systemd | SSH-подключение, статусы и мониторинг. Инсталляция мониторинга и операции обслуживания требуют отдельной проверки прав. Импорт читает `~/.ssh/config` текущего пользователя macOS. |
| Windows | Linux с systemd | Те же SSH-возможности при установленном приложении; путь конфигурации берётся из профиля пользователя Windows. Используйте поддерживаемый приватный ключ или пароль в карточке. |
| Linux | Linux с systemd | SSH-подключение, статусы и мониторинг. Команды выполняются с правами SSH-пользователя; функции, которым нужно повышение прав, используют `sudo -n` или требуют root. |
| macOS / Windows / Linux | Linux с Docker | Состояние контейнеров доступно, когда на узле есть Docker Engine API/CLI и SSH-пользователь имеет к нему доступ. Без доступа контейнеры остаются в состоянии «не проверено»; добавление пользователя в группу `docker` обычно эквивалентно root-доступу. |
| macOS / Windows / Linux | TOS / NAS | Это не универсальное управление NAS. Проверка systemd может быть недоступна; контейнеры зависят от доступности Docker Engine API/CLI. Возможности зависят от SSH-оболочки и прав конкретной модели. |
| macOS / Windows / Linux | macOS по SSH | Возможны только проверки, для которых доступна подходящая команда на удалённой системе. Linux-проверки systemd и Linux reset на macOS не применяются. |
| macOS / Windows / Linux | Windows OpenSSH | Подключение по SSH не означает поддержку Linux-команд приложения. Функции, основанные на systemd, `/proc`, Debian/Ubuntu или Unix shell, для Windows-узла не поддерживаются. |

Сетевой трафик идёт от компьютера приложения прямо к указанному SSH-узлу. Автоматического облачного ретранслятора и поддержки `ProxyJump` в импорте нет.

## Уровни прав

- **Обычный статус и мониторинг:** вход по SSH из карточки. Доступные сведения зависят от прав пользователя; отсутствующие счётчики показываются как неизвестные, а не как ноль.
- **Docker:** требуется доступ к Docker Engine. Доступ к сокету Docker даёт широкие права на узле; назначайте его только доверенному пользователю.
- **Установка или обновление файлов мониторинга:** нужны права записи в целевые системные каталоги; обычно требуется root или рабочий `sudo -n`.
- **Сброс компонентов:** поддерживается только Debian/Ubuntu Linux и требует root либо `sudo -n`. До подтверждения сначала строится план; приложение не запускает сброс на других системах.
- **Управление отдельными службами:** нужны права, которые требует конкретная команда systemd/Docker. Приложение не запрашивает пароль sudo интерактивно.

## Как читать ошибки SSH

| Сообщение | Что проверить |
|---|---|
| Истёк таймаут подключения | Имя/IP, порт, маршрут, firewall и доступность SSH-сервера. |
| Неизвестный или изменившийся host key | Отдельно проверьте fingerprint узла; не обходите `known_hosts`. |
| Ошибка входа | Пользователя, пароль, путь/тип ключа и фразу-пароль в карточке. |
| Недостаточно прав / нет `sudo` | Войдите как root либо настройте для нужной команды `sudo -n`; интерактивный запрос пароля не поддерживается. |
| Неподдерживаемая платформа | Для сброса нужен Debian/Ubuntu Linux; системные команды также зависят от доступности systemd и Docker API. |

Сырые ответы SSH и stderr удалённого узла не следует показывать целиком: они могут содержать локальные пути и сведения о системе. В интерфейсе используются ограниченные категории ошибок и подсказки к исправлению.
