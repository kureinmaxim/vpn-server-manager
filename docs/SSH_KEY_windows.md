# SSH-ключ для второго Windows-ПК

Эта инструкция добавляет новому ПК доступ к VPS через **Tabby** и **VPN Server Manager**. Создайте одну пару на новом ПК и повторите установку её публичной части на каждом нужном VPS. Существующие ключи на серверах сохраните.

Возьмите адрес, логин и SSH-порт из карточки нужного VPS. Команды на сервере ниже предполагают вход под `root`. Если карточка использует другого пользователя, добавляйте ключ в его домашнюю папку и сверяйте в журнале его логин.

## 1. Создайте ключ на новом ПК

Откройте **локальный PowerShell** на новом Windows-ПК. Для второго ПК в примере используется комментарий `windows-pc-02`. Он поможет узнать ключ на сервере.

```powershell
$key = Join-Path $env:USERPROFILE '.ssh\vps_ed25519'
New-Item -ItemType Directory -Force -Path (Split-Path -Parent $key) | Out-Null
if ((Test-Path -LiteralPath $key) -or (Test-Path -LiteralPath "$key.pub")) {
    Write-Host 'Файл ключа уже существует. Проверьте существующую пару или выберите новое имя.'
} else {
    ssh-keygen -t ed25519 -C 'windows-pc-02' -f $key
}
```

При создании задайте фразу-пароль. Затем выведите отпечаток и полный путь. Оставьте это окно PowerShell открытым, чтобы переменная `$key` была доступна в следующем шаге.

```powershell
ssh-keygen -lf "$key.pub"
$key
```

Сохраните отпечаток `SHA256:…` для сверки. Файл `.pub` добавляется на VPS. Файл без `.pub` остаётся на этом ПК и выбирается в приложениях.

## 2. Добавьте публичный ключ на VPS

Войдите на нужный VPS через уже работающий сеанс Tabby или через консоль хостинга. Оставьте этот сеанс открытым. Если парольный SSH-вход уже отключён, воспользуйтесь настроенным устройством или консолью.

В терминале **на VPS** проверьте имя хоста, пользователя и путь к файлу ключей.

```bash
hostname
id -un
/usr/sbin/sshd -T | grep -E '^(pubkeyauthentication|authorizedkeysfile) '
test ! -f "$HOME/.ssh/authorized_keys" || ssh-keygen -lf "$HOME/.ssh/authorized_keys"
```

Для запуска `sshd -T` под обычным пользователем используйте `sudo`, если оно требуется. Если уже есть отпечаток нового ПК, переходите к проверке входа. Если вывод содержит `pubkeyauthentication yes` и `.ssh/authorized_keys`, откройте файл под нужным пользователем.

```bash
install -d -m 700 "$HOME/.ssh"
touch "$HOME/.ssh/authorized_keys"
chmod 600 "$HOME/.ssh/authorized_keys"
nano "$HOME/.ssh/authorized_keys"
```

Пока `nano` открыт, выполните в **PowerShell на новом ПК** следующую команду. Если сеанс VPS открыт на другом устройстве, передайте туда файл `.pub` или только его строку.

```powershell
Get-Content -Raw "$key.pub" | Set-Clipboard
```

Вставьте ключ в `nano` целиком, отдельной строкой в конце файла. Сохраните через `Ctrl+O`, `Enter`, затем выйдите через `Ctrl+X`. Убедитесь, что в списке остались прежние отпечатки и добавился отпечаток нового ПК.

```bash
ssh-keygen -lf "$HOME/.ssh/authorized_keys"
```

## 3. Проверьте Tabby на новом ПК

1. Откройте **Settings → Profiles & connections**. Создайте SSH-профиль или сделайте копию рабочего через **⋮ → Duplicate**. Укажите адрес, логин и порт этого VPS.
2. В **General → Authentication method** выберите **Key**. Через **Add a private key** выберите путь, который вывела команда `$key`, без `.pub`.
3. В **Advanced** выключите **Reuse session for multiple tabs**. Сохраните профиль и запустите его кнопкой **▶**. Если запрошена фраза-пароль ключа, введите её в Tabby. [Настройки SSH-профиля Tabby](https://github.com/Eugeny/tabby/blob/master/tabby-ssh/src/components/sshProfileSettings.component.pug)

В рабочем сеансе **на VPS** выполните поиск по журналу.

```bash
journalctl --since '5 minutes ago' --no-pager |
  grep -E 'Accepted (publickey|password) '
```

Свежая запись `Accepted publickey` должна содержать логин из профиля и отпечаток из шага 1. Если новой записи нет, сравните вывод `printf '%s\n' "$SSH_CONNECTION"` в двух вкладках. Одинаковый адрес и порт клиента означают, что вкладки используют одно SSH-соединение.

## 4. Проверьте VPN Server Manager на новом ПК

1. Откройте карточку VPS и выберите **Редактировать → SSH**. Сверьте адрес, логин и порт с рабочим профилем Tabby.
2. В поле **«Новый SSH-ключ»** или **«Заменить SSH-ключ»** вставьте полный путь из `$key`, без `.pub`. Если карточку импортировали с другого компьютера, замените прежний путь на локальный. Если ключ защищён, введите его фразу в поле **«Фраза-пароль ключа»** и сохраните карточку.
3. Полностью закройте и заново запустите VPN Server Manager. Откройте **«Загрузка серверов»** и дождитесь метрик нужного VPS. Снова выполните команду журнала из шага 3. Нужна **отдельная свежая** запись `Accepted publickey` с тем же отпечатком по времени запуска проверки. `Accepted password` означает, что приложение использовало сохранённый пароль.

### Если VPN Server Manager сообщает о неизвестном ключе сервера

Посмотрите отпечатки ключей **сервера** в уже доверенном сеансе VPS или в консоли хостинга.

```bash
for pub in /etc/ssh/ssh_host_*_key.pub; do ssh-keygen -lf "$pub"; done
```

В PowerShell нового ПК откройте соединение штатным OpenSSH. Введите те же адрес, порт и логин, что в карточке.

```powershell
$vpsAddress = Read-Host 'Адрес VPS'
$sshPort = Read-Host 'SSH-порт'
$sshUser = Read-Host 'Логин SSH'
ssh -o StrictHostKeyChecking=ask -o IdentitiesOnly=yes -o PreferredAuthentications=publickey -p $sshPort -i $key "$sshUser@$vpsAddress"
```

Если OpenSSH предлагает сохранить ключ сервера, подтвердите только после совпадения отпечатка для показанного алгоритма. При несовпадении остановитесь и проверьте адрес VPS и причину смены ключа. После сохранения проверенного ключа сервера в `known_hosts` повторите проверку VPN Server Manager.

## 5. Отметьте, что ПК готов

Для каждого VPS отметьте отдельно **Tabby**, **VPN Server Manager** и нужные **SSH-туннели**. Отключайте парольный вход на VPS после проверки всех нужных устройств и доступа через консоль хостинга. [Общая шпаргалка по SSH-ключам и восстановлению доступа](SSH_KEY_CHEATSHEET_ru.md)
