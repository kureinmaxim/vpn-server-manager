# NAS по SSH

Приложение подключается к NAS по SSH, но не управляет всеми моделями одинаково. Поддержка зависит от прошивки, доступных команд и прав конкретного пользователя. Смотрите [матрицу платформ](SSH_OPERATIONS_MATRIX_ru.md).

## Подготовить NAS

1. В панели NAS включите SSH-сервер и разрешите доступ только из доверенной сети или через VPN.
2. Создайте отдельную учётную запись для мониторинга. Дайте ей только нужные права; для операций, требующих повышения, используйте отдельную ограниченную настройку `sudo -n`, если система её поддерживает.
3. Узнайте адрес NAS и SSH-порт из его сетевых настроек. Убедитесь, что firewall разрешает подключение с компьютера приложения.
4. Независимо проверьте fingerprint SSH host key и сохраните его в `known_hosts`. [Порядок проверки](FIRST_SERVER_ru.md#проверить-ssh-узел).

## Добавить карточку

1. Нажмите **Добавить сервер** и выберите тип узла **NAS**.
2. Укажите название, адрес и SSH-порт.
3. Заполните имя пользователя и пароль или [настройте SSH-ключ](SSH_KEY_ru.md).
4. Сохраните карточку и откройте **Статус** или Monitoring.

## Что будет доступно

- Проверки systemd работают только там, где NAS действительно предоставляет systemd и нужные свойства служб.
- Состояние Docker-контейнеров показывается только при доступе учётной записи к Docker Engine API/CLI. Если доступа нет, результат остаётся «не проверено».
- Добавление пользователя в группу `docker` обычно даёт ему полномочия, эквивалентные root. Не включайте такой доступ только ради зелёного индикатора.
- Системные действия по установке, сбросу или управлению службами могут быть недоступны на NAS либо требовать root/sudo. Сброс компонентов приложения предназначен для Debian/Ubuntu Linux, не для произвольной NAS-прошивки.

При ограниченной оболочке, нестандартном SSH или NAS без systemd используйте только те проверки, которые явно доступны на вашей модели; отсутствие данных не означает, что компонент отсутствует.
