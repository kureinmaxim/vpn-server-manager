# Карточка DNS

Оранжевая кнопка **DNS** на главной странице рядом с Net Tools. Здесь хранятся учётные записи DNS-провайдеров, домены, регистраторы, сроки и записи. Данные лежат в том же зашифрованном файле `.enc`, что и серверы, поэтому попадают в экспорт, импорт и смену ключа (см. [BACKUP_RESTORE_ru.md](BACKUP_RESTORE_ru.md)). В Cloudflare или у другого провайдера приложение ничего не меняет: карточка — это ваш справочник, а правки в DNS вы делаете в панели провайдера. На странице сверху **DNS-провайдеры**, затем **Домены**, внизу **Свой DNS-сервер**.

## Свой DNS-сервер

Карточки своего AdGuard Home лежат в том же зашифрованном файле, что и домены. Их можно добавить вручную (**«Добавить свой DNS»**: название, VPS из списка, DoH или обычный DNS по IP, порт панели) или получить кнопкой **«Обновить»**: удачная проверка по SSH создаёт или обновляет карточку. Если VPS сейчас не отвечает, остаётся последняя сохранённая карточка и шаги подключения. Можно несколько VPS — у каждого своя карточка.

Ниже — как до него достучаться: только через DoH, по адресу Tailscale или порт 53 открыт наружу, и шаги для панели AdGuard, браузера, macOS, Windows, Linux, Android, iPhone, OpenWrt и всей сети Tailscale.

Два режима. **Через DoH-адрес** — когда порт 53 слушает только localhost (типичная схема). Адрес берётся командой `cat /root/dns-doh-url` на VPS и вставляется в поле на странице: он подставляется в шаги и профиль только в этой вкладке, не сохраняется и на сервер не уходит. **Обычный DNS по IP** доступен, если порт 53 слушает Tailscale или другой не-localhost адрес.

Для OpenWrt шаги разделены: без обхода (https-dns-proxy), SSClash/Mihomo, Podkop, Forkop, Zapret, один клиент, гостевая сеть и устройства мимо AdGuard. Одновременно работает только один DNS-стек.

Пароль панели страница не показывает. Проверка только читает состояние по SSH, как кнопка статуса на главной.

## Что есть в карточке

- **DNS-провайдеры** — Cloudflare, Namecheap, GoDaddy, Porkbun, REG.RU, Route 53 или свой. Логин и пароль шифруются; кнопка «Войти в панель» открывает страницу входа.
- **Домены** — провайдер, регистратор, даты регистрации и окончания, автопродление. Срок подсвечивается жёлтым, когда до окончания меньше 60 дней, и красным — меньше 30.
- **Записи** — A, AAAA, CNAME, MX, TXT, NS, SRV, CAA, PTR:
  - делятся на **основные** и **служебные**. Почта, cPanel, проверки домена, SPF/DKIM/DMARC попадают в служебные и свёрнуты. Любую запись можно перенести между группами вручную;
  - адреса локальной сети и Tailscale/Headscale (`10.0.0.0/8`, `192.168.0.0/16`, `100.64.0.0/10` и т. п.) помечены значком «частный»;
  - столбец **Proxy** показывает режим Cloudflare: оранжевое облако — «Проксируется», серое — «Только DNS».
- **Карточка сервера** в развёрнутом виде показывает оранжевое облако с числом DNS-записей, которые указывают на IP этого сервера, их список и перенос. На свёрнутой карточке облака нет: домены — на странице **DNS**.
- **«Перенести на другой VPS»** (кнопка в карточке сервера) показывает каждую запись как «старый IP → новый IP» с кнопками копирования. После правки у провайдера отметьте записи, и карточка DNS обновится.
- **Net Tools** предлагает сохранённые домены и поддомены вместо ручного ввода.

## Импорт файла зоны

Так записи из Cloudflare переносятся в карточку без ручного ввода.

1. В Cloudflare: домен → **DNS → Records → Import and Export → Export**. Скачается текстовый файл зоны (формат BIND).
2. В приложении: **DNS → «Импорт файла зоны»**. Выберите один или несколько файлов и DNS-провайдера для новых доменов.
3. Выберите режим и нажмите **«Импорт»**.

| Режим | Что делает | Когда выбирать |
|---|---|---|
| **Добавить недостающие записи** (по умолчанию) | Новые домены создаются. В существующие добавляются записи, которых ещё нет. Ничего не удаляется | Первый импорт; у провайдера появились новые записи |
| **Заменить записи как в файле** | Для домена, который уже есть в списке, записи, которых нет в файле, удаляются, а новые добавляются. Совпавшие записи сохраняют группу и заметку; обновляется только флаг Proxy | В Cloudflare удалили записи (например, остатки старого хостинга), и карточка должна совпасть с зоной |

Общее для обоих режимов:

- запись совпадает, если у неё те же имя, тип и значение;
- SOA и NS самого домена не импортируются;
- длинные TXT (DKIM), приоритеты MX/SRV и флаг Proxy сохраняются;
- провайдер, регистратор, даты и заметки домена не меняются.

**Защита в режиме замены.** Если в файле есть нераспознанные строки или нет ни одной записи, замена для этого домена отменяется. Появится сообщение «замена отменена…», записи останутся прежними. Так неполный или чужой файл не сотрёт живые записи. Файл, скачанный кнопкой Export в Cloudflare, распознаётся целиком.

После замены приложение пишет итог, например: «example.com: записи заменены — добавлено 3, удалено 26, без изменений 7».

## Cloudflare: «Проксируется» или «Только DNS»

Вверху страницы DNS в Cloudflare может висеть баннер:

> Proxying is required for most security and performance features. Set your DNS records to proxied by clicking "Edit" in the table below, to benefit from DDoS protection, security rules, caching, and more.

Это общая рекомендация, а не ошибка. Cloudflare показывает её, когда записи зоны работают в режиме **DNS only** (серое облако): защита от DDoS, правила безопасности и кэш тогда не действуют. Сайты и сервисы при этом работают; баннер можно закрыть крестиком или не обращать на него внимания.

Включать прокси (оранжевое облако) стоит только для веб-сайтов по HTTP/HTTPS, которые готовы к этому. Оставьте **DNS only** для таких записей:

| Запись | Почему нельзя через прокси |
|---|---|
| Адрес в локальной сети или Tailscale/Headscale (`100.64.0.0/10`, `192.168.x.x`, `10.x.x.x`) | Cloudflare не проксирует частные адреса — до них не добраться из интернета |
| Headscale (координатор Tailscale) | Протокол Tailscale через прокси Cloudflare не работает; это прямо указано в документации Headscale. STUN (UDP 3478) тоже идёт мимо прокси |
| VPN: VLESS-Reality, Hysteria2 (UDP), MTProto, а также SSH | Прокси Cloudflare пропускает только HTTP/HTTPS. Клиент должен подключаться прямо к IP сервера |
| Сайт с сертификатом Let's Encrypt, выпущенным `certbot` на сервере (например, файловый менеджер с `HTTPS_MODE=certbot`) | Схема рассчитана на прямое соединение. Через прокси нужны SSL Full (strict) и Origin CA, а на бесплатном тарифе действует лимит 100 MB на запрос — большие файлы не загрузятся |
| Почта (MX и адреса почтовых серверов) | Прокси не пропускает SMTP/IMAP |

Прокси включают так: Cloudflare → DNS → Records → запись → **Edit** → переключатель **Proxy status**. Через прокси HTTPS доступен только на портах 443, 2053, 2083, 2087, 2096 и 8443. После переключения повторите импорт файла зоны, чтобы флаг Proxy в карточке совпал с Cloudflare.
