# 🔒 Инструменты резервного копирования и управления данными v4.0.3

## 📁 Расположение

VPN Server Manager v4.0.3 использует **встроенные функции** резервного копирования через веб-интерфейс.

**Директории:**
- **`data/`** - зашифрованные данные серверов
- **`uploads/`** - загруженные иконки серверов
- **`logs/`** - логи приложения

## 🚀 Встроенные функции резервного копирования (v4.0.3)

### Через веб-интерфейс (Settings → Data Management):

**1. Экспорт данных**
```
Настройки → Управление данными → Экспорт данных
- Экспортирует только servers.json.enc
- Файл: data_export_YYYYMMDD_HHMMSS.enc
```

**2. Экспорт ключа шифрования**
```
Настройки → Управление данными → Экспорт ключа
- Экспортирует .env файл с SECRET_KEY
- Файл: secret_key_export_YYYYMMDD_HHMMSS.env
- ⚠️ ВАЖНО: Храните в безопасном месте!
```

**3. Экспорт полного пакета**
```
Настройки → Управление данными → Экспорт пакета
- Экспортирует данные + ключ в ZIP
- Файл: full_backup_YYYYMMDD_HHMMSS.zip
- Содержит: servers.json.enc + secret_key.env
```

### Через командную строку (для разработчиков):

**Создать бэкап вручную:**
```bash
# Скопировать текущие данные
cp data/servers.json.enc data/backup_$(date +%Y%m%d_%H%M%S).enc

# Скопировать ключ
cp .env .env.backup_$(date +%Y%m%d_%H%M%S)

# Или через Git
git add data/ .env
git commit -m "Backup: $(date)"
```

## 📋 Импорт данных (v4.0.3)

### Импорт из бэкапа

**1. Импорт данных (с тем же ключом)**
```
Настройки → Управление данными → Импорт данных
- Выберите .enc файл
- Автоматически расшифрует с текущим ключом
- Объединит с существующими серверами
```

**2. Импорт внешних данных (с другим ключом)**
```
Настройки → Управление данными → Импорт внешних данных
- Выберите .enc файл
- Загрузите .env файл с ключом от этого бэкапа
- Автоматически перешифрует пароли на текущий ключ
- Объединит с существующими серверами
```

### Смена основного ключа шифрования

```
Настройки → Управление данными → Сменить главный ключ
- Загрузите новый .env файл с SECRET_KEY
- Все пароли будут автоматически перешифрованы
- Старый ключ больше не понадобится
```

### Проверка ключ-данные

```
Настройки → Управление данными → Проверить ключ-данные
- Загрузите .env и .enc файлы
- Проверит совместимость ключа с данными
- Покажет количество серверов в файле
```

## 💡 Рекомендации и Best Practices

### Регулярное резервное копирование
1. **Еженедельно**: Экспортируйте полный пакет (данные + ключ)
2. **Перед важными изменениями**: Создавайте snapshot через экспорт
3. **Храните бэкапы отдельно**: Не держите на том же компьютере
4. **⚠️ КРИТИЧЕСКИ ВАЖНО**: Делайте копии `.env` файла (SECRET_KEY)!

### Безопасность ключа шифрования
- `.env` файл содержит SECRET_KEY - это мастер-ключ для всех паролей
- Без `.env` файла вы **НЕ СМОЖЕТЕ** расшифровать данные
- Храните несколько копий в безопасных местах:
  - USB-флешка (зашифрованная)
  - Облачное хранилище (зашифрованное)
  - Менеджер паролей (как защищённая заметка)

### Миграция на новый компьютер
```bash
# 1. На старом компьютере
Экспорт пакета → full_backup_YYYYMMDD_HHMMSS.zip

# 2. На новом компьютере
Установить приложение → Настройки → Импорт данных
Выбрать full_backup_*.zip

# Или вручную:
# Распаковать ZIP
# Скопировать secret_key.env → .env
# Скопировать servers.json.enc → data/
```

### Восстановление после потери данных
1. Установите приложение заново
2. Скопируйте `.env` файл из бэкапа
3. Импортируйте данные через интерфейс или скопируйте `.enc` файл

### Legacy документация
Git-бэкапы через каталог `backup_tools/` использовались до v4.0.0. Каталог
удалён из репозитория — используйте встроенные функции приложения, описанные
выше. Если нужны старые скрипты, они остаются в истории git.
