# Первый сервер

Это короткий маршрут от установки приложения до первой проверки сервера. Установку из исходников смотрите в [README](../README.md#quick-start); подключение ключа подробно разобрано в [SSH_KEY_ru.md](SSH_KEY_ru.md).

## Добавить карточку

1. Откройте **Добавить сервер**.
2. Укажите понятное название, IP-адрес или DNS-имя и при желании провайдера.
3. В блоке **SSH-доступ** задайте пользователя, порт, пароль или поддерживаемый приватный ключ. Карточка должна содержать хотя бы один способ входа.
4. Сохраните карточку. Пароли, ключи и другие поля инвентаря хранятся в локальном зашифрованном файле.

Поля `~/.ssh/config` можно импортировать кнопкой в блоке SSH. Импорт запускается только по нажатию и поддерживает ограниченный список директив; см. [матрицу SSH](SSH_OPERATIONS_MATRIX_ru.md).

## Проверить SSH-узел

До первого подключения независимо получите fingerprint host key из панели провайдера или доверенной консоли. На компьютере с приложением выполните `ssh-keyscan -p PORT SERVER_IP > hostkey.tmp`, затем `ssh-keygen -lf hostkey.tmp` и сравните fingerprint. Только после совпадения откройте `ssh -p PORT USER@SERVER_IP` и сохраните ключ в `known_hosts` этого пользователя. Не принимайте неизвестный ключ без сверки.

Затем нажмите **Статус** на карточке. Мониторинг использует сохранённые данные SSH и системный `known_hosts`; приложение не предлагает обход проверки ключа. Если вход не проходит, проверьте адрес, порт, имя пользователя, пароль/ключ и сетевую доступность.

## Дальше

- **Server load** показывает сводку CPU, памяти, диска и сетевого трафика активных серверов.
- **Monitoring** открывает отдельные проверки. Недостающая команда или право отображается как неизвестный результат.
- Docker-сведения доступны только при установленном Docker Engine и правах пользователя SSH на его API/CLI.
- Операции изменения и установки могут требовать root или работающий `sudo -n`; приложение не ждёт интерактивный запрос пароля sudo.

Для сетевой карты, статуса Mesh/DERP и прав на NAS см. [SSH_OPERATIONS_MATRIX_ru.md](SSH_OPERATIONS_MATRIX_ru.md). Перед переносом профиля сделайте [резервную копию](BACKUP_RESTORE_ru.md).
