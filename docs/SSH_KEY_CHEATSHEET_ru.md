# Шпаргалка по переходу с пароля SSH на ключ

В примерах используется Linux VPS и вход под `root`. Подставьте адрес, логин и SSH-порт из своей карточки сервера. Для каждого ПК, Mac и iPhone создайте отдельный ключ. На VPS добавляется только публичная часть. Приватный файл остаётся на устройстве.

**Перед началом** оставьте рабочий сеанс Tabby открытым и проверьте, что можете войти через консоль хостинга. Парольный вход отключайте после проверки всех нужных клиентов.

## Где хранятся ключи

```text
Устройство ── приватный ключ остаётся в SSH-клиенте или в папке .ssh
           └─ публичный ключ (.pub) → отдельная строка в authorized_keys на VPS
```

| Где | Приватный ключ | Публичная часть |
| --- | --- | --- |
| Windows · OpenSSH | `%USERPROFILE%\.ssh\id_ed25519` | `%USERPROFILE%\.ssh\id_ed25519.pub` |
| macOS · OpenSSH | `~/.ssh/id_ed25519` | `~/.ssh/id_ed25519.pub` |
| Linux · OpenSSH | `~/.ssh/id_ed25519` | `~/.ssh/id_ed25519.pub` |
| iPhone · Termius | В **Keychain** внутри приложения | Открыть ключ в **Keychain** и выбрать **Copy Public Key** |
| Linux VPS · вход под `root` | Приватный ключ клиента хранится на его устройстве | `/root/.ssh/authorized_keys` |
| Linux VPS · вход под обычным пользователем | Приватный ключ клиента хранится на его устройстве | `~/.ssh/authorized_keys` в домашней папке этого пользователя |

`id_ed25519` — стандартное имя пары Ed25519 в OpenSSH. В примерах пара для доступа к VPS называется `vps_ed25519`. В Tabby и VPN Server Manager выбирайте файл **без `.pub`**. В `authorized_keys` добавляйте только содержимое файла **с `.pub`**.

## Windows · PowerShell

На новом ПК создайте ключ с фразой-паролем. Если файл уже существует, используйте этот ключ или выберите новое имя. На ПК, где Tabby и VPN Server Manager уже проверены, повторная генерация не нужна.

Для настройки с нуля используйте [пошаговую инструкцию для нового Windows-ПК](SSH_KEY_windows.md).

```powershell
$key = Join-Path $env:USERPROFILE '.ssh\vps_ed25519'
New-Item -ItemType Directory -Force -Path (Split-Path -Parent $key) | Out-Null
ssh-keygen -t ed25519 -C 'windows-pc-01' -f $key
```

В том же PowerShell узнайте отпечаток, скопируйте публичный ключ и выведите путь к приватному файлу для приложений.

```powershell
ssh-keygen -lf "$key.pub"
Get-Content -Raw "$key.pub" | Set-Clipboard
$key
```

## macOS · Terminal

```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh
key="$HOME/.ssh/vps_ed25519"
ssh-keygen -t ed25519 -C 'mac-01' -f "$key"
```

Задайте фразу-пароль. Если файл с таким именем уже есть, сохраните его и выберите другое имя для нового ключа. Затем в том же Terminal выполните:

```bash
ssh-keygen -lf "$key.pub"
pbcopy < "$key.pub"
printf '%s\n' "$key"
```

## iPhone · SSH-клиент

В Termius откройте **Keychain → + → Generate Key**, выберите **Ed25519** и назовите ключ, например `iphone-01`. Откройте созданный ключ и скопируйте **Public Key**. В другом SSH-клиенте ищите создание ключа и копирование его публичной части. [Документация Termius](https://termius.com/)

Добавьте публичную строку на VPS через рабочий сеанс или консоль хостинга по шагам ниже. Затем в профиле VPS на iPhone выберите созданный ключ и откройте новое подключение. Если клиент впервые показывает отпечаток **сервера**, сверьте его через доверенный сеанс VPS. Отпечатки сервера и ключа входа относятся к разным ключам.

```bash
for pub in /etc/ssh/ssh_host_*_key.pub; do ssh-keygen -lf "$pub"; done
```

## Добавить публичный ключ на VPS

### Через открытый Tabby или консоль хостинга

В рабочем сеансе под `root` проверьте путь, который читает OpenSSH.

```bash
/usr/sbin/sshd -T | grep '^authorizedkeysfile '
```

Если вывод содержит `.ssh/authorized_keys`, откройте этот файл.

```bash
install -d -m 700 /root/.ssh
touch /root/.ssh/authorized_keys
chmod 600 /root/.ssh/authorized_keys
nano /root/.ssh/authorized_keys
```

Вставьте публичный ключ (`ssh-ed25519 …`) целиком, отдельной строкой в конце файла. Сохраните существующие строки. В `nano` нажмите `Ctrl+O`, `Enter`, `Ctrl+X`. Проверьте, что в списке появился отпечаток нового ключа.

```bash
ssh-keygen -lf /root/.ssh/authorized_keys
```

### Напрямую с ПК командой SSH

Этот способ подходит, когда командный `ssh` с этого ПК уже может войти на VPS под `root` и `/root/.ssh/authorized_keys` создан. Выполните одну команду добавления для каждого нового ключа. Замените `VPS_IP` адресом VPS, а `SSH_PORT` числом из поля SSH-порта в карточке. Команды дописывают публичную строку в конец файла и сохраняют существующие ключи.

**Windows · PowerShell**

```powershell
$key = Join-Path $env:USERPROFILE '.ssh\vps_ed25519'
$publicKey = Get-Content -LiteralPath "$key.pub" -ErrorAction Stop
$publicKey | ssh -p SSH_PORT root@VPS_IP "{ echo; tr -d '\r'; echo; } >> /root/.ssh/authorized_keys"
```

**macOS или Linux · Terminal**

```bash
key="$HOME/.ssh/vps_ed25519"
ssh -p SSH_PORT root@VPS_IP '{ echo; cat; echo; } >> /root/.ssh/authorized_keys' < "$key.pub"
```

После копирования проверьте отпечаток на VPS командой `ssh-keygen -lf /root/.ssh/authorized_keys`. Если на новом ПК вход ещё не настроен, перенесите его файл `.pub` на устройство с рабочим доступом или вставьте публичную строку через консоль хостинга по предыдущим шагам.

## Проверить новый вход

- **Tabby на Windows и macOS.** В **Settings → Profiles & connections** сделайте копию профиля VPS. В **General → Authentication method** выберите **Key**, затем **Add a private key** и файл без `.pub`. В **Advanced** отключите **Reuse session for multiple tabs**, сохраните профиль и запустите его через **▶**. [Настройки SSH в Tabby](https://github.com/Eugeny/tabby/blob/master/tabby-ssh/src/components/sshProfileSettings.component.pug)
- **VPN Server Manager.** Укажите полный локальный путь к файлу без `.pub` в поле **SSH-ключ** карточки VPS. Если ключ защищён, заполните **Фраза-пароль ключа**. Сохраните карточку, перезапустите приложение и откройте **Загрузка серверов**.
- **iPhone и SSH-туннели.** Откройте новое соединение на телефоне. Если пользуетесь отдельным SSH-туннелем для другого приложения, проверьте и его новым запуском.

Перед тестом запустите журнал в старом Tabby. Открывайте клиенты по одному, чтобы сопоставить запись с конкретным запуском.

```bash
journalctl -f -n 0 -u ssh.service -u sshd.service --no-pager
```

Для каждого нового входа ожидайте `Accepted publickey for root` и отпечаток нужного устройства. `Accepted password` означает, что клиент всё ещё использовал пароль. Если две вкладки Tabby показывают одинаковое значение `SSH_CONNECTION`, они используют одно соединение. `Ctrl+C` останавливает просмотр журнала.

## Отключить пароль на VPS

После проверки всех нужных клиентов оставьте рабочий SSH-сеанс открытым. Убедитесь, что консоль хостинга доступна. Сохраните копию каждого файла конфигурации, который будете менять.

Проверьте основной конфиг, подключения `Include` и правила `Match`. Установите следующие эффективные значения. Для обычных директив OpenSSH использует первое подходящее значение, поэтому простое добавление строк в конец файла может не сработать. [Руководство `sshd_config`](https://man.openbsd.org/sshd_config)

```text
PubkeyAuthentication yes
PasswordAuthentication no
KbdInteractiveAuthentication no
PermitRootLogin prohibit-password
```

Проверьте синтаксис и значения до применения. Если есть `Match`, проверьте соответствующие подключения через `sshd -T -C` с их параметрами. [Руководство `sshd`](https://man.openbsd.org/sshd.8)

```bash
/usr/sbin/sshd -t
/usr/sbin/sshd -T | grep -E '^(port|pubkeyauthentication|passwordauthentication|kbdinteractiveauthentication|permitrootlogin) '
systemctl show -p Id -p ActiveState ssh.service sshd.service
```

При успешной проверке перечитайте конфигурацию активной службы. Если её имя `ssh.service`, выполните `systemctl reload ssh.service`. Если `sshd.service`, выполните `systemctl reload sshd.service`.

Снова откройте новые подключения со всех нужных устройств и приложений. Если новый вход не работает, из оставленного сеанса или консоли восстановите изменённые файлы из копий, проверьте `sshd -t` и перечитайте конфигурацию службы. Закрывайте исходный сеанс после успешной проверки.

## Подключить новый ПК после отключения пароля

1. Создайте отдельный ключ на новом ПК по инструкции для Windows или macOS. Скопируйте публичную часть `.pub`.
2. Войдите на VPS с устройства, у которого уже есть доступ по ключу. Если такого устройства под рукой нет, воспользуйтесь консолью хостинга. Добавьте публичный ключ нового ПК отдельной строкой в `/root/.ssh/authorized_keys` и сохраните существующие записи.
3. На новом ПК укажите приватный ключ в Tabby и других нужных SSH-клиентах. Откройте новое подключение и проверьте `Accepted publickey for root` с отпечатком нового ключа.

Добавленный ключ доступен для следующего SSH-входа сразу после сохранения файла. Парольный вход можно держать отключённым.

## Отозвать ключ потерянного или проданного ПК

1. Войдите на VPS с другого устройства по его ключу или через консоль хостинга. Оставьте этот сеанс открытым. Найдите отпечаток `SHA256:…` старого ПК. Если ПК ещё у вас, запустите на нём `ssh-keygen -lf` с путём к его файлу `.pub`. Если ПК потерян, используйте ранее сохранённый отпечаток или запись `Accepted publickey` от входа, который вы можете привязать к этому ПК. У устройств за одним Tailscale exit node может быть одинаковый IP.
2. На VPS посмотрите отпечатки и номера строк. Комментарий вроде `windows-pc-01` помогает найти нужную строку. Перед удалением сверьте её по отпечатку.

   ```bash
   ssh-keygen -lf /root/.ssh/authorized_keys
   nl -ba /root/.ssh/authorized_keys
   ```

   Чтобы проверить отпечаток одной строки, подставьте её номер вместо `3`.

   ```bash
   sed -n '3p' /root/.ssh/authorized_keys | ssh-keygen -lf -
   ```

3. Сделайте резервную копию и удалите в `nano` только строку с совпавшим отпечатком. Если ключ встречается несколько раз или также указан в другом файле из `AuthorizedKeysFile`, удалите все записи с этим же отпечатком. Остальные записи сохраните. [Формат `authorized_keys`](https://man.openbsd.org/sshd.8#AUTHORIZED_KEYS_FILE_FORMAT)

   ```bash
   backup="/root/.ssh/authorized_keys.backup-$(date +%Y%m%d-%H%M%S)"
   cp -p /root/.ssh/authorized_keys "$backup" && nano -l /root/.ssh/authorized_keys
   diff -u "$backup" /root/.ssh/authorized_keys
   ```

4. Проверьте, что `diff` показывает только удаление записей старого ключа. Затем откройте новый сеанс с другого устройства и убедитесь, что его ключ по-прежнему принимается. Перечитывать конфигурацию SSH не требуется.

Удаление ключа блокирует новые входы с ним. Уже открытый сеанс или туннель продолжит работать, пока его не завершат. Если ПК потерян и его сеанс ещё активен, завершите именно этот сеанс.

## Резервная копия SSH-ключей

**Подготовьте отдельный аварийный ключ с фразой-паролем.** Добавьте его публичную часть на VPS и заранее проверьте один новый вход. Храните аварийный приватный ключ на зашифрованном съёмном носителе, который можно открыть с другого компьютера. Фразу-пароль храните отдельно и проверьте, что сможете получить её без потерянного ПК или телефона. Коды восстановления двухфакторной защиты панели хостинга также должны быть доступны отдельно от повседневных устройств. [Защита пары ключей OpenSSH](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_keymanagement)

Для резервной копии сохраните **файл без `.pub` и соответствующий `.pub`**. Первый нужен для входа, второй — для сверки отпечатка и повторной установки. Укажите путь на уже подключённом и разблокированном зашифрованном носителе. Для разных устройств используйте отдельные папки. В примерах показан рабочий ключ. Для аварийного ключа подставьте имя его файла.

**Windows · PowerShell**

```powershell
$key = Join-Path $env:USERPROFILE '.ssh\vps_ed25519'
$backup = 'E:\SSH-Backup\windows-pc-01'
New-Item -ItemType Directory -Force -Path $backup -ErrorAction Stop | Out-Null
Copy-Item -LiteralPath @($key, "$key.pub") -Destination $backup -ErrorAction Stop
```

**macOS или Linux · Terminal**

```bash
key="$HOME/.ssh/vps_ed25519"
backup='/Volumes/SSH-Backup/mac-01'
mkdir -p "$backup" && cp -p "$key" "$key.pub" "$backup/"
```

На Linux подставьте фактический путь монтирования носителя вместо `/Volumes/…`. После копирования проверьте, что приватный файл на носителе открывается с фразой-паролем и даёт ожидаемый отпечаток. Подставьте путь к **резервному файлу без `.pub`**. Первая команда извлекает только публичную часть. [Руководство `ssh-keygen`](https://man.openbsd.org/ssh-keygen)

```bash
ssh-keygen -y -f "ПУТЬ_К_КОПИИ_ПРИВАТНОГО_КЛЮЧА" | ssh-keygen -lf -
```

После проверки извлеките носитель. Для iPhone можно обойтись без экспорта приватного ключа из приложения: если телефон потеряется, войдите с аварийным ключом, отзовите ключ телефона и создайте новую пару на новом iPhone.

## Восстановить доступ, если все устройства потеряны

### Есть проверенная резервная копия

1. На доверенном ПК разблокируйте носитель. В Tabby выберите аварийный приватный файл в профиле VPS. Если клиенту требуется локальная копия, поместите её в папку `.ssh` текущего пользователя под свободным именем. На macOS или Linux выставьте `chmod 600` на этот файл. На Windows ограничьте чтение файла своим пользователем.
2. Откройте новый SSH-сеанс. Если клиент впервые видит VPS, сверьте отпечаток ключа **сервера** через доверенную консоль или с ранее сохранённым отпечатком. Проверьте в журнале `Accepted publickey` с отпечатком аварийного ключа.
3. Создайте новый ключ для нового ПК, добавьте его публичную часть и проверьте новый вход. После этого отзовите ключи потерянных устройств по их отпечаткам. Если аварийной копии нет, но осталась читаемая резервная копия ключа потерянного ПК, её можно использовать для первоначального входа и затем отозвать этот ключ после проверки нового.

### Копий нет или фраза-пароль утеряна

1. Создайте новую пару на доверенном ПК. Войдите в панель хостинга и откройте консоль VPS. Если можете войти в систему как `root` или получить права через `sudo`, добавьте **новый публичный ключ** в `/root/.ssh/authorized_keys` по шагам выше.
2. Если консоль доступна, но войти в установленную ОС не удаётся, используйте **Rescue / Recovery** хостинга, если он доступен. Загрузка в этот режим может прервать работу VPS. Следуйте инструкции провайдера: определите системный том через `lsblk -f`, смонтируйте его с записью и добавьте публичный ключ в файл **установленной системы**. Если её корень смонтирован в `/mnt/vps`, нужный файл — `/mnt/vps/root/.ssh/authorized_keys`. Права для `.ssh` — `700`, для файла — `600`, владелец — `root`. Затем загрузите VPS в обычном режиме.
3. Проверьте новый вход по ключу и отзовите ключи потерянных устройств. Включать парольный вход по SSH для восстановления не требуется.

Если вход в панель тоже потерян, восстановите учётную запись через поддержку хостинга. Из публичного ключа в `authorized_keys` восстановить приватный ключ нельзя. [Пары ключей OpenSSH](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_keymanagement#key-pairs)
