# Net Tools (4.5.0)

На главной странице нажмите **Net Tools** рядом с **Тест DNS**. Откроется каталог с девятью карточками. Выберите инструмент, введите адрес и нажмите **Запустить проверку**. Язык и тема берутся из настроек интерфейса приложения (русский, английский, китайский; светлая и тёмная темы).

| Инструмент | Что проверяет | Откуда выполняется |
| --- | --- | --- |
| Проверка портов | Соединение с одним TCP-портом, время подключения | Компьютер приложения |
| DNS-запрос / dig | A, AAAA, CNAME, MX, NS, TXT, SOA, PTR, CAA; примеры dig и Resolve-DnsName | Встроенная проверка: Google Public DNS, HTTPS |
| Ping | Четыре ICMP-пакета, системный вывод ping | Компьютер приложения |
| SSL/TLS | Доверие, имя и срок действия сертификата, протокол и шифр | Компьютер приложения |
| WHOIS / RDAP | Регистрационные данные домена или IP | RDAP.org → реестр |
| Reverse IP | Соседние сайты по внешней базе | Переход в Connected |
| HTTP / Fetch | GET, статус, заголовки, первые 64 КиБ ответа | Компьютер приложения |
| Сетевое расположение | Примерное расположение и организация IP | IPinfo |
| Мой внешний IP | Публичный адрес выхода приложения | IPinfo |

Проверки с компьютера приложения используют его сетевое подключение, в том числе системный VPN. В серверном режиме это подключение сервера. Выбора удалённого региона нет. HTTP-прокси из переменных окружения не используются. Адреса запросов к внешним источникам передаются этим источникам только при запуске проверки.

TCP, Ping, TLS, HTTP и геолокация принимают только публичные адреса. Все DNS-ответы проверяются перед соединением, затем соединение закрепляется за выбранным IP; TLS сохраняет проверку исходного имени узла. HTTP-перенаправления показываются без автоматического перехода. RDAP следует только HTTPS-перенаправлениям с повторной проверкой адреса. Ответы показываются как текст, а не исполняемый HTML.

На карточках доступны примеры команд для Linux/macOS и Windows PowerShell с копированием. Это примеры: замените адрес и параметры своими. Команды выполняются вручную. Для Ping должна быть установлена системная утилита `ping`; если её нет, приложение покажет сообщение.

В карточке **DNS-запрос / dig** отдельно доступны `dig example.com`, `dig +short example.com @1.1.1.1` и `Resolve-DnsName example.com`. Первый пример использует настроенный DNS, второй — Cloudflare с кратким выводом. Это DNS-запросы; доступность узла проверяется через Ping или `Test-Connection`. Встроенная кнопка проверки DNS по-прежнему использует Google Public DNS.

Проверки требуют разблокированной PIN-сессии и токена страницы. Одновременно выполняются не более четырёх проверок на процесс приложения. Тайм-аут не доказывает, что порт закрыт: причиной может быть фильтрация. Проверка одного TLS-соединения не заменяет полный аудит TLS. PTR-запись не является списком соседних сайтов.

## Проверка разработки

Автоматические тесты не обращаются к внешним сервисам:

```powershell
python -m pytest tests/test_routes/test_net_tools.py tests/test_services/test_net_tools.py -o addopts="-q --tb=short"
```

Для общего набора тестов на Windows включите UTF-8 (`$env:PYTHONUTF8 = '1'`): существующий тест шифрования создаёт текстовый файл с кодировкой по умолчанию, а читает его как UTF-8. Если системная временная папка недоступна, используйте `--basetemp` с отдельным каталогом внутри тестового окружения.
