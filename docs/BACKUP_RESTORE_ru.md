# Резервная копия и перенос на другой компьютер

Серверы с паролями и карточка DNS (провайдеры, домены, записи) хранятся в **одном зашифрованном файле** `.enc`. Расшифровать его можно только ключом `SECRET_KEY` из `.env`. Каталоги проектов и ботов хранятся отдельно в `config.json`; полный переносимый ZIP включает оба каталога как `catalogs.json`.

## Где лежат данные

| Система | Папка данных приложения |
|---|---|
| macOS | `~/Library/Application Support/VPNServerManager-Clean/` |
| Windows | `%APPDATA%\VPNServerManager-Clean\` |
| Linux | `~/.local/share/VPNServerManager-Clean/` |

Внутри:

- `.env` — строка `SECRET_KEY=…`, ключ шифрования;
- `data/*.enc` — файлы данных; активный указан в `config.json` (`active_data_file`);
- `config.json` — настройки интерфейса, каталоги проектов и ботов;
- `uploads/` — иконки серверов и загруженные файлы.

При запуске из исходников (`python run.py`) используется папка проекта и `.env` в корне проекта — это **другие** данные и, как правило, другой ключ.

## Три вида экспорта

«Настройки» → «Перенести на другой компьютер». Файл сохраняется в выбранную браузером папку.

| Кнопка | Что получите | Когда использовать |
|---|---|---|
| **Экспортировать данные** | `servers_export_<дата>.enc` — серверы и DNS | Копия на тот же компьютер или туда, где уже стоит тот же ключ |
| **Экспортировать ключ** | файл с `SECRET_KEY` | Отдельно сохранить ключ |
| **Полный экспорт** | `UNENCRYPTED_SECRETS_full_transfer_<дата>.zip` | Перенос всего профиля на другой компьютер |

Состав архива **Полный экспорт**:

| Файл | Содержимое |
|---|---|
| `servers_<дата>.enc` | Все серверы с паролями SSH, панели и хостера **и вся карточка DNS**: провайдеры с логинами и паролями, домены, регистраторы, сроки, все записи |
| `SECRET_KEY.env` | Ключ, которым зашифрован `.enc` |
| `catalogs.json` | Все сохранённые проекты и боты, включая системные идентификаторы, команды, задачи, локальные health-проверки и признаки служебных ботов |
| `uploads/` | Иконки серверов (если есть) |
| `README.txt` | Инструкция по восстановлению |

> ⚠️ Архив не зашифрован: в нём лежат зашифрованные серверные данные вместе с ключом к ним. Любой, у кого есть ZIP, сможет прочитать пароли. PIN и секреты Telegram-ботов не экспортируются. Храните архив на зашифрованном диске или в менеджере паролей; не отправляйте в мессенджерах и не кладите в git.

## Восстановление: выберите сценарий

### A. Новая установка без своих данных (или полная замена)

Используйте, если на компьютере приложение только что установлено или его текущие данные не нужны.

1. Закройте приложение.
2. Скопируйте `SECRET_KEY.env` из архива в папку данных приложения (таблица выше) и **переименуйте в `.env`**, заменив существующий.
3. Скопируйте содержимое `uploads/` из архива в `uploads/` папки данных.
4. Запустите приложение и войдите по PIN **этого компьютера** (после установки — `1234` или заданный при первом запуске). PIN хранится в `config.json` установки, а не в архиве; `PIN.txt` — напоминание о прежнем PIN. Чтобы оставить прежний, задайте его в «Настройки» → «Управление PIN-кодом».
5. «Настройки» → **«Импорт файла данных»** → выберите `servers_<дата>.enc` → **«Импортировать и прикрепить»**.
6. Извлеките из ZIP файл `catalogs.json`. Откройте **«Настройки → Перенести на другой компьютер → Импорт списков»**, выберите `catalogs.json`, отметьте проекты и ботов и примените **«Объединить»**. На чистой установке этот режим также восстановит все записи; **«Заменить»** полностью перезапишет выбранные каталоги.

Приложение начнёт работать с этим файлом: появятся все серверы и карточка DNS. У обычной установки с GitHub каталоги остаются пустыми, пока пользователь не добавит свои данные. В персональной сборке может быть отдельный приватный seed; для любого компьютера надежнее восстановить сохранённые списки из `catalogs.json` шага 6. Прежний файл данных не удаляется, но перестаёт быть активным, а прежний `.env` заменён — старые файлы с ним больше не откроются. Если они нужны, сохраните старый `.env` до шага 2.

### B. На компьютере уже есть свои данные — объединить

Используйте, если на втором компьютере уже есть серверы, которые нужно сохранить. `.env` **не заменяйте**.

1. «Настройки» → **«Импорт серверов из другой установки»**.
2. Файл — `servers_<дата>.enc` из архива.
3. Ключ — значение из `SECRET_KEY.env` **после** `SECRET_KEY=` (без самого `SECRET_KEY=`).
4. **«Импортировать и объединить сервера»**.

Что произойдёт:

- создаётся новый файл данных, он становится активным; прежний остаётся в `data/`;
- серверы добавляются, дубликаты (то же имя или IP) пропускаются;
- DNS-провайдеры добавляются, если провайдера с таким названием ещё нет; домены — если такого домена ещё нет;
- все пароли перешифровываются вашим текущим ключом, внешний ключ нигде не сохраняется.

Чтобы перенести каталоги проектов и ботов в этом сценарии, извлеките `catalogs.json` из ZIP и импортируйте его в **«Настройки → Перенести на другой компьютер»**. Выберите объединение, чтобы сохранить локальные записи с другими именами.

Командные строки и задачи из каталога переносятся как данные. Текущий мониторинг не исполняет и не сканирует их; для обнаружения записи нужны поддерживаемые идентификаторы службы, контейнера, процесса или loopback health endpoint.

Существующие домены не дополняются записями из архива. Чтобы добавить записи в уже имеющийся домен, используйте «DNS» → «Импорт файла зоны» (экспорт из Cloudflare: DNS → Records → Export). Режим «Заменить записи как в файле» дополнительно удалит записи, которых в файле нет, — так карточка домена совпадёт с Cloudflare после чистки записей там; регистратор, даты и заметки домена сохраняются. Подробнее — [DNS_CARD_ru.md](DNS_CARD_ru.md).

## Проверить копию, не импортируя

«Настройки» → **«Проверка соответствия ключ-данные»**: выберите `.enc`, вставьте ключ. Приложение покажет, подходит ли ключ, сколько в файле серверов и доменов DNS.

## Частые ошибки

| Сообщение | Причина | Что делать |
|---|---|---|
| «Файл не может быть расшифрован… создан с другим ключом» при «Импорт файла данных» | В `.env` другой ключ | Сценарий A (заменить `.env`) или сценарий B (импорт с внешним ключом) |
| «Неверный ключ шифрования» в сценарии B | Вставлен не тот ключ или вместе с `SECRET_KEY=` | Скопируйте только значение после `=` |
| После переустановки все файлы не открываются | Установщик создал новый ключ (Windows до 4.9.0) | Восстановите `.env` из архива (сценарий A). С 4.9.0 установщик Windows сохраняет существующий `.env` |
| Серверы на месте, DNS пустой | Импортирован старый экспорт (до 4.6.0) или активен файл без DNS | Импортируйте свежий «Полный экспорт» или загрузите файлы зоны |

## Совместимость версий

- Карточка DNS хранится в `.enc` начиная с **4.6.0**. Версии 4.5.x и старше такой файл не прочитают — список серверов будет пустым. Не открывайте новый файл в старой версии.
- Пока в карточке DNS нет данных, файл остаётся в старом формате и читается любой версией.

## Кнопка «Первый запуск → Импортировать из архива»

На экране блокировки есть кнопка импорта ZIP-архива, но в текущей версии она не работает (сервер не обрабатывает загрузку). Восстанавливайте данные сценарием A или B.
